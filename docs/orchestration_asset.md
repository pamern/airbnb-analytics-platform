Hãy sửa lỗi tích hợp `dagster-dbt` hiện tại.

## Lỗi đang gặp

Khi chạy `price_retraining_job`, Dagster báo:

```text
DagsterInvariantViolationError:
Expected to find dbt manifest metadata on asset gold_price_model_features,
but did not. Did you pass in assets that weren't generated by @dbt_assets?
```

Stack trace cho thấy lỗi phát sinh tại:

```python
dbt.cli(["build", "--select", model], context=context).wait()
```

trong:

```text
orchestration/assets/ml_assets.py
```

Nguyên nhân là:

* `gold_price_model_features` và `gold_cluster_model_features` đang được khai báo bằng `@asset` thông thường;
* nhưng `DbtCliResource.cli()` lại nhận `context=context`;
* `dagster-dbt` vì vậy cố tìm manifest metadata vốn chỉ có trên asset được tạo bởi `@dbt_assets`.

## Mục tiêu sửa

Chuyển hai dbt Gold model sang cách tích hợp chính thức bằng `@dbt_assets`, để Dagster nhận đúng manifest, lineage và dependency.

Không sửa logic ML, artifact, registry, metric hoặc MotherDuck writer.

## Yêu cầu bắt buộc

### 1. Khảo sát trước khi sửa

Dùng CodeGraph và đọc các file liên quan:

* `orchestration/assets/ml_assets.py`
* `orchestration/definitions.py`
* resource dbt hiện tại
* resource MotherDuck hiện tại
* `orchestration/jobs/`
* `dbt/dbt_project.yml`
* `dbt/profiles.yml` hoặc cấu hình profile hiện tại
* `dbt/models/gold/`
* `pyproject.toml`

Xác định chính xác:

* dbt project directory;
* profiles directory;
* manifest path;
* asset keys hiện tại;
* asset keys mà `@dbt_assets` sẽ sinh ra;
* jobs đang select asset nào.

Không kết nối MotherDuck và không materialize remote pipeline trong quá trình sửa.

### 2. Tạo cấu hình `DbtProject`

Tạo hoặc chuẩn hóa một nơi duy nhất quản lý dbt project, ví dụ trong:

```text
orchestration/resources/dbt.py
```

Dùng:

```python
from dagster_dbt import DbtCliResource, DbtProject
```

Định nghĩa project bằng path tương đối từ repository root, không hard-code đường dẫn Windows tuyệt đối.

Ví dụ định hướng:

```python
DBT_PROJECT_DIR = REPO_ROOT / "dbt"

dbt_project = DbtProject(
    project_dir=DBT_PROJECT_DIR,
)
```

Nếu profile nằm trong cùng thư mục `dbt`, cấu hình resource tương ứng.

Chỉ gọi:

```python
dbt_project.prepare_if_dev()
```

ở vị trí phù hợp với lifecycle của Definitions, không tạo side effect không cần thiết khi import test.

### 3. Khai báo dbt assets bằng `@dbt_assets`

Tạo file riêng nếu phù hợp, ví dụ:

```text
orchestration/assets/dbt_assets.py
```

Dùng:

```python
from dagster import AssetExecutionContext
from dagster_dbt import DbtCliResource, dbt_assets
```

Khai báo asset definition thật sự:

```python
@dbt_assets(
    manifest=dbt_project.manifest_path,
    select="gold_price_model_features gold_cluster_model_features",
)
def airbnb_gold_dbt_assets(
    context: AssetExecutionContext,
    dbt: DbtCliResource,
):
    yield from dbt.cli(
        ["build"],
        context=context,
    ).stream()
```

Nếu cú pháp `select` cần dùng dbt selection expression khác theo version hiện tại, dùng cú pháp phù hợp nhưng chỉ chọn đúng hai model:

```text
gold_price_model_features
gold_cluster_model_features
```

Không chạy toàn bộ dbt project.

### 4. Xóa wrapper asset sai

Xóa hoặc ngừng sử dụng hai wrapper Python asset đang tự gọi:

```python
_run_dbt_gold(...)
```

và:

```python
@asset
def gold_price_model_features(...)

@asset
def gold_cluster_model_features(...)
```

Không giữ hai asset key trùng với asset key do `@dbt_assets` tạo ra.

Xóa helper `_run_dbt_gold()` nếu không còn được dùng.

### 5. Sửa dependency của ML assets

Cho các ML assets downstream phụ thuộc vào asset keys sinh ra từ dbt manifest.

Ưu tiên dependency-only bằng:

```python
@asset(deps=[AssetKey("gold_price_model_features")])
```

và:

```python
@asset(deps=[AssetKey("gold_cluster_model_features")])
```

nếu ML asset tự đọc DataFrame qua MotherDuck resource.

Không khai báo function parameter cho dbt asset nếu không cần nhận object Python từ upstream.

Phải xác nhận chính xác asset key thực tế được sinh ra. Nếu translator hiện tại thêm schema hoặc prefix, dùng đúng `AssetKey`, không phỏng đoán.

### 6. Cập nhật jobs

Cập nhật:

* `price_retraining_job`
* `segmentation_retraining_job`
* `full_ml_pipeline_job`

để select đúng dbt assets mới và các downstream ML assets.

Yêu cầu:

* `price_retraining_job` chỉ chạy dbt asset cần cho price và chuỗi price;
* `segmentation_retraining_job` chỉ chạy dbt asset cần cho segmentation và chuỗi segmentation;
* `full_ml_pipeline_job` chạy cả hai;
* không tạo duplicate asset selection;
* không chạy toàn bộ dbt project ngoài hai model cần thiết.

### 7. Cập nhật Definitions

Trong `orchestration/definitions.py`:

* đăng ký dbt assets mới;
* bỏ wrapper assets cũ;
* giữ nguyên MotherDuck resource;
* giữ nguyên ML assets, checks và jobs ngoài phần dependency cần sửa;
* không tạo nhiều `Definitions`;
* không thêm schedule hoặc sensor.

### 8. Không sửa ngoài phạm vi

Không thay đổi:

* `ml/price_modeling`;
* `ml/listing_segmentation`;
* thuật toán;
* feature;
* hyperparameter;
* model artifact logic;
* model registry schema;
* metric logic;
* prediction logic;
* cluster assignment;
* MotherDuck table writer;
* dbt SQL model;
* dbt schema nghiệp vụ.

Không commit hoặc push.

## Kiểm thử bắt buộc

Sau khi sửa, chạy:

```powershell
uv run dagster definitions validate -m orchestration.definitions
```

```powershell
uv run python -m compileall -q orchestration
```

```powershell
uv run python -c "from orchestration.definitions import defs; print('definitions loaded')"
```

Nếu có test orchestration hiện tại, chạy chúng.

Có thể chạy:

```powershell
uv run dbt parse --project-dir .\dbt --profiles-dir .\dbt
```

để bảo đảm manifest được tạo và hợp lệ.

Không:

* chạy `dagster dev` lâu dài;
* materialize job;
* query MotherDuck;
* ghi dữ liệu remote;
* chạy full dbt build.

## Kết quả cần báo cáo

Sau khi hoàn thành, báo cáo:

1. Nguyên nhân lỗi.
2. File đã tạo.
3. File đã sửa.
4. Wrapper asset nào đã xóa hoặc ngừng dùng.
5. `DbtProject` được đặt ở đâu.
6. Manifest path được xác định thế nào.
7. Tên function `@dbt_assets`.
8. Hai dbt model được select.
9. Asset key thực tế của:

   * `gold_price_model_features`;
   * `gold_cluster_model_features`.
10. Dependency của price và segmentation assets sau sửa.
11. Jobs đã được cập nhật thế nào.
12. Các lệnh kiểm thử và kết quả.
13. Phần nào chưa được xác minh do không materialize remote pipeline.

Ưu tiên sửa tối thiểu, đúng convention của `dagster-dbt`, không tạo kiến trúc song song và không làm thay đổi logic ML hiện tại.
